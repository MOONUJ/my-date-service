# Development tickets

모든 구현 작업은 이 디렉터리의 티켓으로 범위와 승인을 관리한다.

## 상태

```text
proposed → approved → in-progress → done
                         └────────→ blocked
```

- `proposed`: 작성됐지만 아직 승인되지 않은 작업
- `approved`: 승인됐지만 바로 시작하지 않는 대기 작업
- `in-progress`: 승인 후 현재 구현 중인 작업
- `done`: 구현, 검증, push와 필수 CI를 모두 완료한 작업
- `blocked`: 외부 결정, 권한, 자격 증명 또는 상태 변화가 있어야 재개할 수 있는 작업

티켓 파일의 `status`와 디렉터리는 항상 일치해야 한다. 승인 전에는 티켓 작성과 읽기 전용 조사 외의 구현을 시작하지 않는다.

## 식별자와 파일명

모든 상태 디렉터리를 확인해 다음 미사용 순번을 `TICKET-0001` 형식으로 선택한다. 파일명은 `TICKET-0001-short-slug.md`처럼 작성하며 이동할 때 이름을 유지한다.

## 승인과 완료

사용자는 티켓 ID를 지정해 승인한다. 승인을 받고 즉시 시작할 때는 `approved_at`과 `started_at`을 기록하고 `in-progress`로 이동한다. 범위가 실질적으로 달라지면 proposed로 되돌려 다시 승인받는다.

완료에는 코드 작성만이 아니라 티켓의 검증 계획 수행, diff 리뷰, 커밋, push와 필수 CI 성공이 포함된다. 완료 증거를 티켓에 기록한 뒤에만 `done`으로 이동한다.
