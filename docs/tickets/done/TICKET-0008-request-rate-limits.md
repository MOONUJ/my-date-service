## 목적과 사용자 가치

로그인 공격과 반복 검색이 비밀번호 해시 계산, D1, 카카오 장소 API와 OpenAI 호출을 무제한 소비하지 않게 해 개인용 서비스의 계정과 무료 사용량을 보호한다.

## 구현 범위

- 로그인·회원가입·계정 삭제 재인증 실패에 클라이언트 네트워크 단위의 짧은 고정 구간 제한 적용
- 인증된 사용자의 장소 검색과 취향 저장에 사용자 단위 제한 적용
- 제한 초과 시 안정적인 `REQUEST_RATE_LIMITED` 오류 코드, 안전한 한국어 메시지, HTTP 429와 `Retry-After` 반환
- 성공 여부와 무관하게 보호해야 하는 요청을 집계하되, 정상적인 페이지 초기화와 로그아웃은 제한하지 않음
- D1에 원문 IP, 이메일, 검색어와 취향을 저장하지 않고 서버 비밀값으로 만든 불투명한 제한 키와 만료 시각·횟수만 저장
- 만료된 제한 행을 정상 요청 중 제한적으로 정리하고 사용자 계정 삭제 시 사용자 단위 제한 행을 함께 제거
- UI에서 제한 상태를 기존 결과와 구분해 안내하고 중복 검색 제출을 막으며 `Retry-After` 동안 검색 버튼 상태를 안전하게 복구
- 제한 경계, 사용자 격리, 만료, 오류 응답, 외부 API 미호출과 UI 복구 테스트

## 제외 범위

- Cloudflare 유료 Rate Limiting, KV, Durable Objects, Queues 또는 별도 보안 SaaS 도입
- CAPTCHA, 이메일 인증, 계정 잠금, 차단 목록과 관리자용 해제 화면
- 여러 데이터센터 사이의 강한 일관성이나 분산 공격에 대한 완전한 방어
- 카카오·OpenAI 계정 자체의 예산·쿼터 설정 변경
- 프로덕션 배포, 원격 D1 migration 적용과 secret 등록

## 기술적 접근

- 기존 D1에 만료 가능한 고정 구간 카운터 migration을 추가하고 한 요청 안에서 조건부 갱신해 병렬 요청에서도 상한을 크게 넘기지 않게 한다.
- 인증 전 요청은 `CF-Connecting-IP`를 배포 환경의 `RATE_LIMIT_SECRET`으로 HMAC 처리한 불투명 키로 묶는다. 헤더가 없는 로컬·테스트 환경에는 주입 가능한 명시적 fallback을 사용하며 신뢰할 수 없는 전달 헤더는 사용하지 않는다.
- 인증 후 요청은 세션에서 확인한 사용자 ID 범위로 제한하고 요청 본문의 사용자 식별자는 신뢰하지 않는다.
- 제한 검사는 비밀번호 PBKDF2와 외부 장소·AI 호출 전에 수행해 비용이 큰 작업을 보호한다.
- D1 오류 시 로그인·검색 전체를 무조건 허용하지 않고 기존 안전한 503 경계를 유지한다. 제한 키, 원문 입력과 자격 증명은 로그에 남기지 않는다.
- 구체적인 상한은 개인용 MVP 정상 사용을 방해하지 않는 보수적 기본값으로 코드 상수와 테스트에 명시한다.

## 비용 영향

- 외부 서비스와 유료 Cloudflare 제품을 추가하지 않는다.
- 보호 요청마다 소수의 D1 read/write가 늘지만, 반복 요청이 카카오·OpenAI 호출로 이어지는 것을 차단해 전체 비용 위험을 낮춘다.
- 만료 행 정리를 요청당 제한해 D1 write 급증을 피하고 개인용 무료 티어 규모를 전제로 한다.

## 보안·개인정보 영향

- 인증 시도 제한으로 비밀번호 추측과 PBKDF2 자원 고갈 위험을 낮춘다.
- 원문 IP와 이메일을 제한 테이블에 저장하지 않으며, HMAC 키는 서버 secret으로만 주입하고 저장소·클라이언트·로그에 노출하지 않는다.
- IP 기반 제한은 공유 네트워크 사용자를 함께 제한할 수 있으므로 짧은 구간과 명확한 재시도 시간을 사용한다.
- D1 기반 제한은 전용 엣지 rate limiter만큼 강한 분산 방어가 아니며 MVP의 비용·복잡도 경계 안에서 기본 남용을 완화하는 수준이다.

## 검증 계획

- 고정 시계와 D1 fixture로 최초 허용, 경계 요청, 초과, `Retry-After`, 구간 만료와 키 격리 테스트
- 인증 실패 반복 시 비밀번호 검증이 상한 이후 실행되지 않는지 테스트 double로 확인

## 결정 사항

- Cloudflare의 별도 유료/전용 제한 제품 없이 기존 D1로 개인용 MVP 수준의 제한을 구현한다.
- 인증 전 제한 키 보호를 위해 `RATE_LIMIT_SECRET` 서버 secret을 필수로 사용한다. 프로덕션 등록은 별도 배포 작업으로 남긴다.
- 계정 잠금 대신 짧은 고정 구간 429를 사용해 영구적인 사용자 차단과 복구 운영 부담을 만들지 않는다.
