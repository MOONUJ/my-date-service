## 목적과 사용자 가치

검색 결과를 공급자 응답 순서대로 보여주는 현재 동작을 개선해, 사용자의 취향과 이동 수단에 맞는 장소 TOP 3를 비용 없이 일관되게 추천하고 그 이유를 확인할 수 있게 한다.

## 구현 범위

- 취향 문장과 장소의 이름·카테고리·태그를 정규화해 일치 근거를 계산
- 취향 일치와 이동 수단별 정보 가용성에 기반한 결정론적 점수화
- 점수순 전체 결과와 TOP 3 생성, 동점에서는 원래 공급자 순서를 유지
- 실제 구조화 데이터에서 확인된 근거만 사용한 짧은 한국어 추천 이유 생성
- 취향 일치가 없거나 교통 정보가 부족한 경우 과장하지 않는 fallback 이유 제공
- 점수화·정렬·근거 생성의 정상 흐름과 경계 조건 테스트 추가

## 제외 범위

- OpenAI API, 다른 LLM, 임베딩 또는 Vectorize 연동
- 사용자 취향 저장, 회원가입·로그인, D1 또는 기타 영속 저장소
- 카카오 외 추가 지도 공급자와 새로운 외부 API 호출
- 주차·영업시간·거리 등 공급자 응답에 없는 사실의 추론
- UI 재설계, 프로덕션 배포와 CI/CD 구성

## 기술적 접근

- 기존 검색 오케스트레이션 안에서 사용할 순수 함수 기반 scorer를 분리해 입력이 같으면 결과도 같게 만든다.
- 한국어·영문 입력의 대소문자, 공백과 일반 구두점을 정규화하고 의미를 임의로 확장하지 않는 단순 토큰 일치를 사용한다.
- 취향 근거를 가장 큰 가중치로 두고, 자차는 확인된 주차 정보, 대중교통은 확인된 교통 안내의 존재에 작은 가산점을 준다.
- 내부 점수는 정렬에만 사용하고 기존 API 계약은 불필요하게 확장하지 않는다.
- 점수가 같으면 공급자 원래 순서를 유지하고 정렬 후 `rank`를 다시 부여한다.
- 추천 이유는 일치한 카테고리·태그와 확인된 교통 정보만 조합하며, 근거가 없으면 일반 후보임을 명시한다.

## 비용 영향

- 외부 API 호출과 유료 AI 호출을 추가하지 않는다.
- 작은 검색 후보군에 대한 문자열 비교만 수행하므로 Cloudflare Workers 무료 티어에서 무시할 수 있는 수준의 CPU 증가로 제한한다.
- 향후 LLM 도입 전 개인화 효용을 검증할 수 있어 불필요한 모델 비용을 피한다.

## 보안·개인정보 영향

- 취향 문장은 기존 요청 처리 중에만 사용하며 새로 저장하거나 로그에 남기지 않는다.
- 취향이나 검색 결과를 새로운 외부 서비스에 전송하지 않는다.
- 기존 입력 길이 검증과 안전한 텍스트 렌더링 경계를 유지한다.
- 추천 이유에 공급자 원본에 없는 사실이나 사용자 취향 원문 전체를 노출하지 않는다.
