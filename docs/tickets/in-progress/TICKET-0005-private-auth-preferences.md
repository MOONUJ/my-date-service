## 목적과 사용자 가치

개인 사용자가 이메일과 비밀번호로 안전하게 로그인하고 자신의 데이트 취향을 저장·수정해, 이후 검색마다 취향 문장을 다시 입력하지 않아도 개인화 추천을 받을 수 있게 한다.

## 구현 범위

- D1 migration으로 사용자, 세션과 현재 취향을 저장하는 최소 스키마 구성
- 이메일·비밀번호 기반 계정 생성, 로그인, 로그아웃과 현재 사용자 조회 API
- 비밀번호를 Web Crypto 기반의 salt가 포함된 강한 파생 키로 저장하고 원문은 저장·로그하지 않음
- 추측하기 어려운 세션 토큰을 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키로 발급하고 D1에는 토큰 해시와 만료 시각만 저장
- 모든 취향 조회·수정 쿼리를 인증된 사용자 ID로 제한
- 취향 문장의 길이·형식 검증과 저장·수정 UI 추가
- 로그인 전에는 인증 화면, 로그인 후에는 취향 설정과 기존 장소 검색 흐름을 제공
- 회원가입은 환경 설정으로 명시적으로 허용한 경우에만 노출·처리하고 기본값은 닫힘으로 유지
- 인증 실패, 중복 이메일, 만료·폐기 세션, 잘못된 입력과 D1 오류를 안전한 코드·메시지로 처리
- 로컬 D1 migration, Worker API와 모바일·키보드 흐름에 대한 자동·브라우저 검증 추가

## 제외 범위

- 이메일 인증, 비밀번호 재설정, 소셜 로그인과 다중 인증
- 공개 회원가입 운영, 초대 시스템, 관리자 화면과 역할 기반 권한
- OpenAI API 기반 추천, 검색·추천 기록 저장과 계정 삭제
- 카카오·Cloudflare 프로덕션 secret/binding 등록과 프로덕션 배포
- 유료 Cloudflare 기능 또는 별도 인증 SaaS 도입

## 기술적 접근

- 기존 단일 TypeScript Worker 안에 인증·취향 저장 경계를 분리하고 D1 prepared statement와 migration을 사용한다.
- 비밀번호 파생은 Workers Web Crypto에서 지원되는 표준 알고리즘을 사용하고 파라미터를 레코드와 함께 버전 관리한다. 로그인 비교는 timing 차이를 줄이는 방식으로 처리한다.
- 세션은 짧고 고정된 유효기간을 두며 로그아웃과 만료 시 서버에서 폐기할 수 있는 불투명 토큰 방식으로 구현한다.
- 브라우저에는 세션 토큰이나 비밀번호를 JavaScript 저장소에 두지 않는다. 상태 변경 API는 쿠키 속성과 요청 출처 검증을 함께 적용해 CSRF 경계를 둔다.
- 이메일에는 고유 인덱스, 세션 토큰 해시와 만료 시각에는 조회·정리용 인덱스를 두어 D1 row read를 제한한다.
- `ENABLE_SIGNUP`이 명시적으로 활성화되지 않으면 회원가입 API는 닫힌 오류를 반환한다. 개인 계정 생성 후 다시 비활성화하는 운영 절차를 문서화한다.

## 비용 영향

- Cloudflare D1 무료 플랜 범위에서 작은 개인용 사용자·세션·취향 데이터만 저장한다.
- 2026-09-04 확인 기준 무료 플랜은 일 500만 row read, 10만 row write, 계정 총 5GB와 DB당 500MB 한도이며, 일 한도를 넘으면 자정(UTC)까지 쿼리가 실패한다. 구현 직전과 배포 전 공식 가격·한도를 다시 확인한다.
- 로그인·현재 사용자·취향 처리마다 인덱스를 사용하는 소수 쿼리로 제한하고 자동 재시도를 추가하지 않는다.
- 유료 플랜 활성화와 실제 원격 D1 생성은 이 티켓에 포함하지 않는다.

## 보안·개인정보 영향

- 이메일, 비밀번호 파생값과 취향 문장이라는 개인정보를 새로 저장하므로 최소 수집·사용 목적과 외부 전송 여부를 README에 명시한다.
- 비밀번호 원문, 세션 토큰, 취향 원문과 전체 D1 행을 로그·오류·분석 이벤트에 남기지 않는다.
- 쿠키 기반 인증, 사용자 ID 범위 제한, 입력 상한, 세션 만료·폐기와 안전한 오류 응답을 테스트한다.
- 공개 회원가입은 기본적으로 닫고 개인 계정 생성 시에만 사용자가 명시적으로 설정을 켜는 비공개 운영을 권장한다.
- 계정 삭제와 보존 기간 정책은 별도 사용자 결정을 받아 후속 티켓에서 구현하며, 그 전에는 프로덕션 공개 운영을 하지 않는다.

## 결정 사항

- 개인용 MVP에 맞춰 공개 회원가입이 아니라 기본 비활성화된 비공개 회원가입을 권장한다. 이 티켓 승인은 이 운영 범위에 대한 승인이다.
- 구조화된 최소 사용자 데이터에는 기존 원칙대로 D1을 사용한다. 이 티켓 승인은 migration과 로컬 D1 binding 추가까지 포함하지만 원격 D1 생성·유료 플랜·배포는 포함하지 않는다.
- 세션은 클라이언트 저장 JWT 대신 서버에서 폐기 가능한 `HttpOnly` 쿠키를 권장한다. 서비스 정의의 JWT 표현은 목적보다 안전한 이 구현으로 구체화한다.
- 계정 삭제와 데이터 보존 기간은 프로덕션 공개 전에 별도 티켓과 사용자 결정을 거친다.
